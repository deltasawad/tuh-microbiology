# LINE LIFF — ระบบส่งตรวจสิ่งแวดล้อม

งานจุลชีววิทยา โรงพยาบาลธรรมศาสตร์เฉลิมพระเกียรติ

แยกเป็น 2 ฝั่งตามลักษณะงานจริง — ผู้ส่งตรวจใช้มือถือใน LINE, นักเทคนิคการแพทย์ใช้คอมพิวเตอร์

| ไฟล์ | ใคร | อุปกรณ์ | ต้องล็อกอินอะไร |
|---|---|---|---|
| `index.html` | ผู้ส่งตรวจ (8 หน่วยงาน) | มือถือ ในแอป LINE | LINE (อัตโนมัติ) |
| `admin.html` | นักเทคนิคการแพทย์ | คอมพิวเตอร์ จอกว้าง | บัญชีเจ้าหน้าที่ (`auth.js`) |

## 1. ค่าตั้งต้น (ใส่ครบแล้ว)

### LIFF ID → `js/liff-config.js` ✅ ใส่เรียบร้อยแล้ว

```js
liffId: '2011162657-GE5HlbQR',
```

LIFF URL สำหรับเปิดจากใน LINE: https://liff.line.me/2011162657-GE5HlbQR

เอามาจาก **LINE Developers Console → Channel (Messaging API) → แท็บ LIFF → Add**

| ช่อง | ค่าที่ต้องตั้ง |
|---|---|
| LIFF app name | TUH Microbiology |
| Size | **Full** |
| Endpoint URL | `https://tuh-microbiology.vercel.app/liff` |
| Scopes | ✅ `profile` ✅ `openid` |
| Bot link feature | On (Aggressive) |

> ⚠️ ถ้าไม่ติ๊ก `profile` → `liff.getProfile()` จะ error 403 และแอปจะตกไปโหมดพัฒนา

### Supabase URL / anon key → `../js/supabase-config.js`

ใช้ไฟล์เดียวกับเว็บหลัก **ไม่ต้องใส่ซ้ำ** ถ้าย้าย LIFF ไป deploy คนละโดเมนค่อยก๊อปไฟล์นี้ตามไป

### สิ่งที่ห้ามใส่ในโฟลเดอร์นี้

**LINE Channel Access Token** — ผู้ใช้เปิดอ่านไฟล์ JS ได้ทุกบรรทัด
token อยู่ฝั่งเซิร์ฟเวอร์ที่ `api/notify/broadcast.js` เท่านั้น

## 2. รันฐานข้อมูลก่อน 1 ครั้ง

```bash
# Supabase Dashboard → SQL Editor → วางไฟล์นี้ → Run
supabase_liff_migration.sql
```

เพิ่มคอลัมน์ `line_user_id`, `line_display_name`, `source` ให้ตาราง `bookings` และ `reports`

> โค้ดออกแบบให้ทำงานได้แม้ยังไม่รัน — ถ้าเจอ error 42703/PGRST204 จะตัดคอลัมน์ LINE ออกแล้วบันทึกใหม่อัตโนมัติ
> แต่จะย้อนดูไม่ได้ว่าใบไหนส่งโดย LINE ของใคร และหน้า "ใบของฉัน" จะถอยไปค้นด้วยชื่อผู้เก็บตัวอย่างแทน

## 3. ทดสอบบนคอมพิวเตอร์โดยไม่ต้องมี LINE

```bash
node test_server.js
```

เปิด http://localhost:4180/liff/index.html

ยังไม่ได้ใส่ LIFF ID → เข้า **โหมดพัฒนา** อัตโนมัติ ใช้โปรไฟล์จำลอง กรอกฟอร์มได้ครบทุกขั้น

> โหมดพัฒนาเปิดได้เฉพาะ `localhost` / `127.0.0.1` / เปิดไฟล์ตรง ๆ เท่านั้น
> พอขึ้นโดเมนจริงจะปิดตัวเองทันที **ไม่ต้องไปสลับสวิตช์เอง** (ดู `isDevHost()` ใน `liff-config.js`)
> ถ้าขึ้นโดเมนจริงแล้วยังไม่ได้ใส่ LIFF ID หน้าจอจะขึ้น error บอกให้ไปตั้งค่า ไม่ใช่แอบใช้โปรไฟล์จำลอง

อยากดูภาพรวมทั้งระบบในหน้าเดียว เปิด http://localhost:4180/liff/preview.html
(กรอบมือถือ 3 ขั้น + การ์ด Flex + หน้าลงผลฝั่งคอม — ข้างในเป็นแอปจริง กดใช้งานได้)

`test_server.js` เป็น **DRY-RUN** ไม่ส่ง LINE จริง — ถ้าจะส่งจริงรัน `node test_server.js --real`

## 4. เรื่องแคชของ LIFF (สำคัญ)

เบราว์เซอร์ในแอป LINE แคชแรงกว่าเบราว์เซอร์ปกติมาก **แก้โค้ดแล้วผู้ใช้จะยังเห็นของเก่า**

ทุกครั้งที่แก้ไฟล์ ให้ขยับเลขเวอร์ชันท้าย `<script>` ในหน้า HTML:

```html
<script src="/liff/js/liff-app.js?v=20260819a"></script>   →   ?v=20260819b
```

แล้วดูเลขที่ท้ายจอแอป (`LIFF v20260819a`) เพื่อยืนยันว่า LINE โหลดเวอร์ชันใหม่แล้ว
หน้า HTML ทั้งสองไฟล์ใส่ `<meta http-equiv="Cache-Control">` กันแคชไว้ให้แล้ว

## 6. คีย์ลัดในหน้าลงผล (`admin.html`)

ออกแบบให้คีย์ผลหลายสิบแถวโดยไม่ต้องละมือไปจับเมาส์

| ปุ่ม | ผลลัพธ์ |
|---|---|
| `Enter` / `↓` | ลงแถวถัดไป **คอลัมน์เดิม** |
| `↑` | ขึ้นแถวก่อนหน้า |
| `Tab` | ไปคอลัมน์ถัดไป |
| ปุ่ม *เติมค่าปกติทุกแถว* | เติม No growth / 0 ให้ทุกแถว แล้วค่อยแก้เฉพาะแถวที่ผิดปกติ |

เลือก **Growth** ในแถวไหน ช่องสรุปผลแถวนั้นจะเด้งเป็น *ไม่ผ่าน* ให้อัตโนมัติ

## 7. ความปลอดภัย

- ฟอร์มผู้ส่งตรวจ **ไม่มีช่องกรอกผลตรวจ** โดยตั้งใจ
- `report_items.bacteria_count` / `item_result` แก้ได้จาก `admin.html` เท่านั้น
- บังคับซ้ำที่ฐานข้อมูลด้วย RLS — สิทธิ์ `anon` เพิ่มใบส่งตรวจได้ แต่แก้ผลไม่ได้
- ถ้าบันทึกผลไม่สำเร็จแม้แถวเดียว ใบจะ**คงสถานะรอตรวจไว้** ไม่หลุดจากคิวทั้งที่ยังไม่มีผล
